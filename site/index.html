WHY

The same dozen operations, written once

Every launch needs to claim fees, buy, burn, snapshot holders and airdrop. When each project carries its own copy, a bug fixed in one stays broken in the rest. pumpkit is those operations as plain functions, with every production incident already handled.

Plain JavaScript

ESM, no build step, no TypeScript toolchain. Install it, or copy src/ into your project and read every line.

ctx first

Every function takes a context, then plain values. Nothing reads process.env behind your back.

bigint at the edge

Amounts are raw units as bigint. Floats appear in logs only, so nothing is lost to rounding.

No "burn everything"

You burn, sell and send what you measured, never the wallet balance. The dev bag stays where it is.

GOTCHAS

Mistakes you do not have to make

Each of these cost real money or a production incident. The fix is already in the code. The README lists all fourteen.

Token-2022, not classic SPL

pump.fun mints use Token-2022. Assume the classic program and you compute the wrong token account: the buy confirms, no tokens arrive. Always mintProgramId().

Never act on the whole balance

The engine wallet often holds the dev bag. Burning "everything" burns that too. Measure before and after, then act on the difference.

v2 pools hold your fees

PumpSwap v2 pools park creator fees inside the pool until someone sweeps them. claimCreatorFees({ mint }) sweeps first.

"Expired" does not mean failed

A slow RPC reports block height exceeded for a transaction that landed. pumpkit checks the signature before throwing, so a retry never buys twice.

Redeploys overlap

Two containers run together for a few seconds. An advisory lock on a reserved connection and a crash-safe ledger keep a round from running twice.

Airdrop rent adds up

Opening a token account costs about 0.002 SOL per holder. pumpkit pays it once per wallet, and only when the drop is worth it.
